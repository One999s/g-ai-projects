# ADR-003：先完成独立 Chat HTTP 子集，不并行造 app-server 空壳

日期：2026-10-10。状态：实现与受控loopback HTTP合同测试通过；真实厂商/真实模型 NOT_RUN。

## 取舍

先实现一个标准库、非流式的 OpenAI-compatible Chat Completions JSON-object adapter。仅包含 `POST /v1/chat/completions`、单choice、assistant文本JSON、两项限定文件提案。它不是全厂商统一客户端，也不表示已验证任何真实OpenAI/Claude/Grok模型。

Codex固定审计版本只支持Responses，app-server又涉及子进程双向请求、审批桥接和会话生命周期。其接入设计继续保留在 [ADAPTERS](ADAPTERS.md)，本轮不同时建立第二条未闭环实现。Chat的messages/choices/response_format与Responses的input/output/text.format不得混用。

## 安全与权限

- 端点来自本地公开配置，模型无法改host/URL。HTTPS证书正常验证；不跟随重定向，不读取代理环境自动改路由
- 普通HTTP仅允许明确配置的loopback地址，并要求allow_loopback_http=true；测试服务器只绑定127.0.0.1。远端/私网服务也必须由操作者明确配置，不自动扫描或发现
- 密钥只通过环境变量名称引用，运行时读取，不接受CLI密钥实参、不序列化到配置/SQLite/事件，不打印原始HTTP异常或错误body。已知密钥出现在导出状态/配置/模型回复时拒绝（含JSON转义后的字符串检查）
- 模型只提案，响应必须逐项等于用户请求的file.write + file.verify。shell、额外路径、额外字段、自动approve、tool_calls/function_call均拒绝
- 计划与usage结算同SQLite事务发布；计划初态ready，执行仍经原Kernel审批，没有自动调用工具或桌面

## 预算与不确定性

model_calls单独记录调用成本事实，任务执行仍使用原tasks/approvals/operations。调用前SQLite事务预留成本，两个连接不能重复使用同一份剩余额度。另有max_calls硬次数上限，防零价格配置导致无限调用。

预留 = 配置input_token_reservation × 输入报价 + max_completion_tokens × 输出报价。请求UTF-8字节上限只是本地策略，并非已验证tokenizer。收到有效usage后按配置报价结算，公开标记这是quoted cost，不是供应商最终账单；缓存/推理等细项不在已有总量之外重复累加。

缺usage、已发送后超时/取消/HTTP异常：保留完整预留，financial_state=unknown，禁止后续新模型调用，禁止自动重试或切换模型再付一次钱。发送前确定取消/拒绝：可记not_sent与0。usage超过预留时保留真实报告的token数与计算额，标记policy violation并阻断新调用，不截断为预算上限。

配置指纹固定在账本中，改预算/报价/端点不静默清空历史。未提供“猜0成本/删历史重试”的CLI。对未知调用应先人工核对供应商事实，未来通过明确的账务核对功能结案，不能擅自释放预留。

## 模型选择与状态迁移

只允许配置allowlist内显式select，选择跨进程重启保存，只影响未来规划。已生成/批准的计划不改变。传入旧任务作context时，仅导出TaskSummary的task_id、goal、state、completed_steps、remaining_steps；新路径/正文为本次请求显式给定内容。没有自动导出历史会话、隐藏推理、原始供应商reasoning字段或环境凭据。

允许列表中的模型必须满足同一个已配置协议子集。max_completion_tokens与旧max_tokens由操作者明确二选一，不同时发送、不因400自动改参；不同协议厂商需要独立profile和验收。

## 超时/取消与证据边界

单次请求，无自动重试/退避/回退。socket I/O timeout与连接后的monotonic deadline watchdog防慢响应/慢header拖住已建立连接；输出有字节上限。取消在发送前、响应后和读取间检查，阻塞I/O期间最多等连接/读取被超时终止；操作系统DNS解析仍非本进程可保证的硬实时期限。取消/客户端断开不等于服务端没生成或没计费。

只用本机HTTP fixture和假密钥验证传输/账本。没有真实厂商调用、真实费用、真实模型质量或Windows端到端证据。TLS真实服务、供应商别名/计量/限流语义与实际tokenizer需后续明确授权后分别验证。
