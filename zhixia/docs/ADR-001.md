# ADR-001：轻内核 + 协议适配，先证明恢复与审批

- 日期：2026-10-10
- 状态：Phase0 采用；Windows 分发与实机边界待 Phase1 验证
- 输入：[REUSE-AUDIT](REUSE-AUDIT.md) 中固定 commit 的来源与许可检查

## 决策

采用 Python 3.11+ 标准库内核，SQLite 任务账本，CLI 优先。Phase0 运行依赖为零，测试使用 unittest。后续原生桌面执行用独立 Python UIA adapter（优先评估固定版 pywinauto），浏览器用 Playwright adapter；Codex app-server 可作为另一个受控执行/规划引擎，但不拥有知夏系统身份、总权限或长期记忆。

不要把本项目机械套进 Java 业务中台，也不在第一轮引入微服务、向量库、工作流集群或桌面 UI 框架。Python 与 SQLite 足够证明本轮目标，并接近 Windows UIA 生态。代价是未来可执行包体积、升级、进程隔离和依赖许可仍须单独验证。标准库可运行不等于已有签名的 Windows 安装包。

## 最小职责

1. `contracts.py`：显式动作、任务摘要、状态、Provider/ExecutionAdapter/MemoryRepository 协议
2. `providers.py`：fake 路由测试、能力/预估预算门控、真实配置的 fail-closed 校验
3. `kernel.py`：SQLite 状态、审批、不可自动重放的副作用账本、取消、恢复与审计
4. `tools.py`：仅允许工作区文件创建/验证；持久 intent → 原子无覆盖发布 → 内容验证 → durable receipt
5. `cli.py`：本地可信操作员入口；逐步执行而非后台无限循环

## 状态与恢复

`ready → waiting_approval → ready → running → ready/succeeded`

- 拒绝/暂停时取消：`cancelled`
- 执行异常或旧 worker 停止后的 `running`：`needs_reconciliation`
- 只读核对证明目标内容吻合：记录 receipt，再推进步骤
- 缺失/冲突/不确定：留在 `needs_reconciliation`，人工调查；明确放弃则 `failed`
- 运行中取消不承诺回滚：先保存已发生副作用证据，随后 `cancelled`

操作包含 operation_id、arguments_hash、policy_version、approval_id、idempotency_key、状态及 receipt。SQLite 事务原子领取操作并消费审批。恢复需要本地操作员确认旧 worker 已停止；当前没有分布式 lease、网络 worker 或自动抢占。核对证明的是当前期望文件内容存在，不证明是谁写入；已有相同内容可以满足目标，不能宣称本次新建。

## 审批与工具边界

模型不能修改数据库、直接执行工具或批准自己。未知动作 fail-closed。Phase0 所有写动作都审批，完整参数、task、step、workspace 和策略版本进入 binding hash。审批 1–3600 秒、一次性消费，参数变化即失效。只读验证不需审批。

工具优先级固定为：原生 API → CLI → DOM/UIA → 视觉。未来 shell 也只接受结构化 allowlist、固定 cwd、明确参数、超时和输出上限，禁止任意字符串 shell。外发、生产、支付等风险域当前无执行实现，不能通过批准一个字符串来打开旁路。未经验证的 Agent 无完整桌面权限。

应用层路径检查不能对抗恶意同用户进程和 TOCTOU。当前不声称 OS 沙箱。Windows 后续须验证低权限 broker、进程树取消、junction/reparse、中文/长路径和网络策略。

## 模型与记忆

OpenAI / Claude / Grok / DeepSeek / Ollama / vLLM / 兼容 API 经各自 adapter 接入，而不是假定所有供应商都有同一种 wire format。跨 provider 只导出经选择的可见任务摘要、事实和结果引用，不带隐藏推理或 opaque reasoning blob。fake-a/fake-b 仅证明合同与路由；真实延迟、成本、限流、上下文和工具调用能力未验证。

六类记忆：working、episodic、semantic、procedural、prospective、experience。本轮只有接口；未来按 user/project/device/task scope 隔离，支持来源、纠错、删除、TTL 和对检索结果的同权限过滤。不能把 SQLite 事件流宣传为已经完成长期记忆。

## 放弃的路线

- 直接 fork Codex：Rust 内部接口易变，官方 app-server 尚实验性；身份/记忆/业务流程不足以构成 fork 理由
- 把 UFO 整套 agent loop 引为内核：依赖与权限面大，重复任务/审批控制；仅参考其成熟 Windows 执行经验
- Browser Use 作为原生桌面执行器：它面向浏览器，不能控制 Notepad，默认权限还需收窄
- 第一版自研视觉识别：成本大且不利于确定性验收，UIA/DOM 不可用时再明确升级权限

## 重审条件

真实 Windows 验证失败、Python 打包/升级不可接受、app-server 稳定接口无法完成已证实需求，或多设备/多租户成为真实已授权需求时，另建 ADR。禁止仅为未来想象一次性扩架构。
