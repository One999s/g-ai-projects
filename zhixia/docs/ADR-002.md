# ADR-002：Notepad 候选适配器复用内核，两阶段审批

日期：2026-10-10。状态：代码与离线合同测试已实现，Windows 真机 NOT_RUN。

## 决策

扩展现有 Kernel 的可信 `create_actions` 和 adapter 注入入口，复用原有 tasks/approvals/operations/events 状态机。新增 adapter_id 数据库绑定、适配器 policy_version 和具有唯一 parent 的 task_children 表，禁止一个启动任务重复创建输入任务。原 Phase0 文件执行测试保留通过；DDL 为仅新增表/元数据，不重写既有数据。

桌面候选使用独立状态文件以避免误用 CLI，但数据库结构和状态机仍是同一实现。普通文件 CLI 打开 desktop 数据库会因 adapter_id 不符拒绝。

## 为什么两阶段

在启动记事本之前还没有 PID/HWND，不能把未知窗口伪装成已审批身份：

1. 启动提案绑定设备、固定系统 Notepad exe、adapter 版本、后续输入全文/保存路径、不覆盖和UTF-8合同。第一次审批只批准启动，不输入
2. 启动动作记录实际 PID、HWND、进程创建时间（防 PID 复用）、进程实际 exe 与 adapter 版本
3. 只有该启动任务完成才生成输入任务；第二次审批同时绑定上述窗口/进程身份及全文/路径/设备。每个启动只允许一个输入任务，由 SQLite 唯一约束保住并发
4. Kernel传显式task/operation上下文，adapter按精确operation领取状态核验，不按全库参数hash猜任务。每次 GUI 操作前重查身份及取消；未知窗口/控件/进程变更即停止

## 可验范围和保守限制

采用 pywinauto 0.6.8 固定源码与已核分发包哈希，候选组合为 Windows CPython 3.11 x64 + six 1.16.0 + comtypes 1.2.0 + pywin32 306，见 [分发审计](WINDOWS-DEPENDENCIES.md)。该旧版本没有官方3.11实测保证，**此候选组合仍未安装/运行验证**。

实现只支持一个空白 Edit 控件与经典原生 Save As 对话框的窄路径。tabbed Notepad、packaged/rehosted进程、未知控件树、非UTF-8落盘均 fail-closed。不得宣传为已兼容现代Win11记事本。上层协议可替换 backend，将来新版Notepad需要独立验证adapter。

保存只用批准窗口子树内精确标签唯一匹配的UIA Expand/Invoke；不使用menu_select模糊查找、全局Ctrl+S、set_focus或键鼠后备。Value.SetValue/CurrentValue读写明确限定控件pattern，未知树即拒绝。

只读 check 检查平台与包元数据，不 import pywinauto（该包顶层会初始化COM）；真正UIA只在明确 run --enable-uia 且消费审批后延迟加载。拒绝管理员运行，不申请UIAccess，不访问摄像头/麦克风，不使用截图/视觉/剪贴板。

## 证据与恢复

- 启动收据：设备、exe、PID/HWND/进程创建时间、adapter版本、实际调用类型
- 输入保存收据：同一身份与 `uia_input_and_save` 调用证据，声明真实 backend 或合同测试
- 成功验收：已有 durable UIA 调用收据 + 独立磁盘逐字节 verifier，通过后才给 `real_windows_acceptance=true`
- 测试注入的 backend 永远输出 `execution_mode=contract_test`、`real_windows_acceptance=false`。测试fixture写文件只是协议测试，生产backend无文件写入代码
- 启动或GUI输入保存的收据丢失：保持 needs_reconciliation；即使文件存在且内容相符，也不能证明经历了正确UIA路径，禁止重放。人工核查/放弃后另启新任务
- 仅独立verify步骤中断可使用既有UIA收据进行只读恢复。取消不自动关闭窗口或撤销已输入内容，避免额外未批准副作用

## 尚未解决的生产边界

同一OS用户可信、无抗恶意本地进程强隔离；hostname hash只作本机绑定提示，不是多设备认证。代码路径检查不抵御TOCTOU。GUI焦点可并发变化，不应在验收时与用户同时操作桌面；原生UIA合同测试不能代替真机验收。执行broker/Windows ACL/job object与现代Notepad兼容仍待后续里程碑。
